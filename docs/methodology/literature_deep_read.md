## What this changes in our interpretation

**Established design, independent implementation.** Our log-mel CNN and CNN+GRU are ordinary model families. The current 16 kHz, 64-band, full-five-second, small-encoder/mean-pooling implementation is deliberately cheaper than the audited historical recipes. It should be named a small from-scratch baseline, not “PiczakCNN,” “SB-CNN,” or a reproduction of Qiao's CRNN. None of the inspected papers establishes the score that this different implementation must obtain.

**Representation reduction is a real modeling choice.** Averaging frequency before the recurrent layer discards direct frequency-bin identity; stacking remaining frequency positions keeps it. Mathematically, these are different maps, so one cannot treat the change as a free implementation optimization. A frequency-preserving variant would require its own parameter count, nonrecurrent capacity control and matched data exposure. It is a candidate if diagnostics support it, not a presumed improvement.

**Training duration is not transferable by epoch number.** Patch sampling, overlap, augmentations and clip length determine the number of examples and updates. Report unique original clips, optimizer updates and actual feature/audio exposure. Comparing “50 epochs” across incompatible patch definitions does not equalize resources.

**From-scratch and transfer results are different regimes.** The primary methods audited here train their task models without describing an external pretrained encoder. Our from-scratch comparison should remain separate from any later pretrained audio/image system, including its pretraining dataset, possible ESC-50 overlap, license, frozen/trainable parameters and extra data. A strong transferred model can be a practical reference, but cannot alone answer whether recurrence helps the small from-scratch encoder.

## Proposed bounded recipe and diagnostic ladder

These are design recommendations, not executed results or frozen decisions. The study owner should freeze the selected recipe before running it.

1. **Repair measurement first.** Verify cache/frontend compatibility, source-exclusion membership and checkpoint provenance. Run a real-audio tiny-subset optimization check using only training clips. Log final-checkpoint evaluation-mode training loss/accuracy alongside validation. A falling online loss on synthetic frequency bands is insufficient to validate audio/label alignment.
2. **Use a cheap anchor.** On the same cached log-mel representation, concatenate per-band temporal mean and standard deviation (128 features for 64 bands), standardize using the actual training subset and fit a regularized linear classifier. Select its regularization on development validation with a small declared grid. Report it as a new diagnostic baseline, not a reproduction of a paper's MFCC classifier. Its speed helps expose whether the learned encoder adds value.
3. **Stabilize the current models before expanding them.** Start a predeclared longer CNN/CRNN learning-curve pilot with equal full-clip exposure, same batch/optimizer schedule and equal checkpoint opportunities. A 30-epoch initial ceiling is a resource-planning choice; use observed per-epoch cost to set the safety cap and decide whether curves warrant a longer fixed-budget run. Preserve all partial/failed attempts. Do not select an architecture from an early crossing of curves.
4. **Separate mechanisms.** Compare recurrence with a nonrecurrent head of similar parameter budget over the same encoder features. Apply deterministic permutation of encoded time tokens at evaluation to measure order dependence; a mean head should be invariant. An order-sensitive drop is a probe under distribution shift, not proof of useful temporal reasoning.
5. **Add one regularizer at a time.** If training metrics show fitting with poor validation, evaluate a declared training-only mask or mixup condition under equal search opportunity. Mixed labels require a soft-label loss or an equivalent weighted loss. Do not apply sound transformations indiscriminately when class meaning may change; inspect class behavior and avoid augmentation fitting on test feedback.
6. **Freeze confirmation.** Keep fold 5 untouched until final recipe selection. Report this held-out confirmation separately from an explicitly exploratory or properly nested five-fold study. If rotating outer folds after all recipe decisions used folds 1–4, disclose that history; merely calling the loop “cross-validation” does not restore an untouched confirmation boundary.

## Claims this reading does not establish

- No result has been independently reproduced by reading the papers.
- No evidence shows that frequency preservation, mixup, extra depth or GRU will improve our current controlled system.
- No universal minimum number of seeds, convergence epoch, target accuracy, or noise robustness follows from these sources.
- Full search logs, all source code details and every authors' checkpoint-selection decision were not independently reconstructed. Qiao's fold/selection ambiguity remains unresolved.
- The reviewed sources are a targeted method audit, not an exhaustive 2026 state-of-the-art or novelty search.
