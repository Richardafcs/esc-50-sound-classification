# Infra Phase 1 — Epoch-Boundary Resumable Training

## What was actually implemented

The research package retains its original CNN, CNN+BiGRU, and Attention models, historic experiments, and held-out evaluation guards. New experiments now commit **only completed epochs** to `last.pt`. This checkpoint is the authoritative recovery boundary; `history.json`, `best.pt`, `validation.json`, `training_evaluation.json`, and `validation_predictions.csv` are derived/repaired from the committed checkpoint if an interruption occurs during their writes.

`last.pt` contains the model state, AdamW optimizer (including moments), optional cosine scheduler, Python / NumPy / CPU and CUDA Torch RNG states, the DataLoader shuffle generator, exact train-only normalization, data cache hash, original manifest and code identity, completed-epoch history, and the validation-selected best model state plus its validation predictions. It is loaded with `torch.load(weights_only=True)`. The checkpoint format remains schema 2 for compatibility with existing inference tools, with an additional `resume_state: {version: 1}` field; historical schema-2 checkpoints *without* this field are **not** resumable.

The `best.pt` artifact is now **inference-only**: it includes the selected model and normalization but intentionally omits optimizer/scheduler state, because these would otherwise refer to the final epoch rather than the best epoch. Always resume from `last.pt`, never from `best.pt`.

## Commands

Run from the repository root after installing the package (`pip install -e .`) and completing `esc50 preflight`:

```bash
# Controlled example: stop at the end of the second completed epoch.
python -m esc50_sound train \
  --cache data/esc50_features.npz \
  --model crnn_freq_ta \
  --output runs/attention_ta_seed101 \
  --epochs 60 --batch-size 32 --seed 101 --threads 3 \
  --device cpu --scheduler cosine --max-seconds 3600 \
  --pause-after-epochs 2

# Continue same run: model, seed, optimizer, split, learning rate,
# maximum epochs, and preprocessing are inherited from its manifest.
python -m esc50_sound resume-train \
  --output runs/attention_ta_seed101 \
  --max-seconds 3600
```

A user may pause again at a specified **cumulative** epoch via `--pause-after-epochs 10`. This is an operational execution control, not an experiment hyperparameter. Resuming refuses model, data, or train-protocol overrides because none are accepted by the command. Checkpoint selection still uses minimum validation cross-entropy. Neither command evaluates the held-out test fold.

## Failure semantics

- **Complete epoch:** commit `last.pt` atomically, repair/write derived files, update `run.json`.
- **Wall-clock budget within an epoch:** discard that epoch's optimizer updates from the durable experiment; replay the entire epoch from the last committed snapshot. In-process work already performed is lost by design.
- **Failure between `last.pt` and sidecars:** resume reconstructs sidecars from the committed checkpoint, then proceeds.
- **Failure before epoch 1 commit:** no resumable state exists; start a new run.
- **Previously completed run or any recorded test access:** resumption is refused.
- **Changed cache bytes, model manifest, Python package source hash, OS/architecture environment, PyTorch / NumPy version, or compute device:** strict replay is refused rather than silently presenting a new experiment as identical.
- **Checkpoint generated by older versions:** inference remains possible as before, but resume is refused unless the new explicit state is present.

The time budget is checked before each optimizer batch; it is a **soft** budget and does not preempt a slow batch, validation, or filesystem operation. CUDA replay across arbitrary kernels/distributed processes is not yet validated. Different hardware/driver/library combinations may produce different floating-point results even if RNG state is restored. Exact equality assertions are for the tested CPU platform and package version.

## Verified evidence — synthetic only

- Eight new tests pass, including uninterrupted vs interrupted/resumed training for a CNN and an Attention-CRNN with Dropout, SpecAugment, and Cosine LR; a simulated exception in the middle of an epoch; repair after incomplete sidecar writes; cache tampering / held-out-test-access rejection; and tensor-only RNG serialization.
- Non-runner core suite: 162 tests passed; Pipeline/Study suite: 13 passed; Runner suite: 16 passed. Total: **191 passes, run in three groups**.
- No ESC-50 WAV dataset or real feature cache was available for actual audio training. Therefore this is NOT an ESC-50 accuracy result or a demonstration of real-data end-to-end performance.
- Historical weights and recorded test metrics are not modified.

## Known work remaining

1. Concurrent-run directory locking / leasing (currently assumes a single owner per run directory).
2. Explicit cancellation and kill/restart integration on external job schedulers.
3. Crash/replay stress testing under genuine process termination and disk-full failures (exception and sidecar-corruption tests have been performed).
4. True mid-epoch sampler / worker-prefetch / optimizer-step replay, if justified by training costs.
5. CPU/GPU/distributed determinism acceptance criteria and the ability to diagnose expected nondeterminism.
6. Original WAV data and features to perform authentic ESC-50 experiments with the approved split protocol.
